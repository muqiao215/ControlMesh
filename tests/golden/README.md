# ControlMesh Golden Fixtures

Golden fixtures compare Python reference behavior with TypeScript consumers.

Current status: Python-reference provider fixtures and the task-lifecycle parity matrix are active.

The source-aware provider admission matrix is also active:
`fixtures/runtime/execution-provenance-sandbox.matrix.json` is generated by the production
Python policy and one-shot boundary and is checked for exact case inventory and drift.

`fixtures/tasks/lifecycle.matrix.json` is generated by executing the production Python
ownership paths. It covers create, tell, ask_parent, resume, cancel, recovery, workspace,
and artifact behavior, including negative and containment cases. It is the mutation parity
gate: another runtime must produce the same normalized observations before mutation
ownership can move.

Generate after an intentional Python behavior change:

```bash
pnpm generate:lifecycle-golden
```

Check committed fixtures without writing:

```bash
pnpm check:lifecycle-golden
```

Check source-aware provider admission drift directly:

```bash
pnpm check:execution-provenance-golden
```

Run the live Python oracle and private TypeScript candidate together, then verify the
digest-bound rollback gate:

```bash
pnpm check:lifecycle-parity
```

The gate produces structured JSON-path differences and fails on value drift, missing
cases, extra cases, stale Python fixtures, or a stale rollback artifact. A green gate keeps
Python as production/rollback owner and does not expose public mutation APIs.

Required critical fixtures:

- `tasks/lifecycle.matrix.json`
- `providers/fake.success.json`
- `providers/fake.timeout.json`
- `providers/fake.error.json`
- `runtime/execution-provenance-sandbox.matrix.json`

The matrix Schema at `schema/task-lifecycle-matrix.schema.json` is authoritative for
cross-language fixture shape. Production Python remains authoritative for behavior.
